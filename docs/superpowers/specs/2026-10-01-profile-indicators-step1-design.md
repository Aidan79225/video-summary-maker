# 人物側寫 第一步：投入量＋具體度 — 實作設計

日期：2026-10-01　依據：issue #24（人物側寫：表現指標 — 設計）的「順序」第 1 步。

本文件只記錄第 1 步要做的事，以及 issue 沒有定下、這裡做了決定的地方。原則（不加總、不排名、只跟同儕比、最小樣本、每個數字能點回去）照 issue。

## 範圍

做：

- `Session`（會期）表，文章掛上會期。
- 指標計算與快取（`ProfileStat`），每天重算。
- 人物側寫 API、文章清單的證據篩選。
- 發言者頁上的側寫區塊、新的 `/method` 頁（說明公式）。

不做（留給後面的步驟）：

- 出席率。LYAPI 的 `/meets` 有結構化的 `會議資料.出席委員`，可以做，但要新的同步指令（issue 規劃的 `sync_ly_records`），併在立法產出那一步。
- 議題分布、追問率、立法產出、表決（issue 的 #2、#4、#5、#6）。

## 決定

### 會期從文章的會議名稱解析

文章的 `meeting` 欄位本來就寫了會期：

| 來源 | 會議名稱（實測） | 會期名稱 |
|---|---|---|
| 立法院 | `第11屆第5會期財政委員會第3次全體委員會議`、`第11屆第5會期第23次會議`、`第11屆第3會期第1次臨時會第2次會議` | `第11屆第5會期`（臨時會併入它所屬的會期） |
| 臺中 | `第4屆第8次定期會`、`第4屆第2次臨時會` | 原樣：`第4屆第8次定期會`、`第4屆第2次臨時會` |
| 新北 | `第4屆第8次定期會 市政總質詢` | `第4屆第8次定期會` |

- 立法院：`第(\d+)屆第(\d+)會期`。議會：`第(\d+)屆第(\d+)次(定期會|臨時會)`。全形數字先轉半形。
- 解析不出來（例如立法院的「立法院朝野黨團協商」）就不掛會期，不計入任何指標；重算報告列出各來源有幾篇已完成的文章因此沒算到。
- 立法院的全院委員會、公聽會片段（約 6%）沒有「會議資料」，會議名稱改用頂層的「會議名稱」（去掉「（事由：…）」）。既有文章用 `backfill_meetings` 補。
- `Session.start_date`／`end_date` 是**資料涵蓋範圍**：掛在這個會期的文章（任何狀態）最早與最晚的日期。不是官方起訖——同儕比較時大家的涵蓋範圍一樣，這樣才公平；頁面上寫「資料涵蓋 X～Y」。

### 人與文章的對應

- 講者欄位以「、」分隔（聯合質詢）。每個名字用「同來源、同名、任期涵蓋文章日期」對到 `Membership`，再取 `Membership.person`。跟 `link_article` 同一套規則，但先把該來源的任期全部載入記憶體，不要每篇查一次。
- 對不到任期的名字：不計入，計算報告列出這些名字與篇數（通常是名冊的寫法不同，要人看）。
- `ProfileStat` 以 **Person** 為鍵，不是 Membership：同一會期內換黨會切成兩段任期，但那是同一個人。

### 母體（同儕）

- 某會期的母體 = 該來源中，**屆別與會期相同**、任期與會期涵蓋範圍有重疊的所有人（`start_date` 為空視為無限早、`end_date` 為空視為現任；屆別不知道時只看日期）。議會的任期沒有日期，不看屆別的話換屆後舊會期會混進新議員。
- 名冊同步遇到換屆（連任也算）要結束舊的一段、開新的一段，不能改寫舊任期的屆別與職位。
- 排除那一屆的任期上 `role` 是 `議長` 或 `副議長` 的人（新北有這欄）：他們只主持、不質詢，放進母體只是一堆零。下一屆才當選議長的人，這一屆照常計算。立法院、臺中沒有這欄就不排除，文件寫明。
- 對得到人、卻不在母體裡的講者要列在重算報告裡，不能靜悄悄地少算。
- 母體裡沒有任何發言的人，投入量算 0——這正是要比較的。

### 指標

只算 `status=READY` 的文章（只有它們有頁面可以點回去）。處理中的不算，方法頁寫明。

**投入量**（區塊 key `volume`）

| key | 名稱 | 值 | n | 單位 |
|---|---|---|---|---|
| `speeches` | 發言次數 | 該會期講者包含他的文章數（聯合質詢每人各算一次） | 同值 | 次 |
| `speaking_minutes` | 發言總時長 | Σ（`duration_seconds` ÷ 該篇講者人數）÷ 60，取到小數一位 | 發言次數 | 分鐘 |

聯合質詢的時長平分給每位講者：分不出誰講了多久，平分是唯一不用猜的公式。

顯示順序：市議會時長在前（總質詢一次幾十分鐘、業務質詢十幾分鐘，時長比次數有意義），立法院次數在前。由 API 依來源排好。

投入量沒有「分母」，不套最小樣本；但母體少於 5 人時不給百分位。

**具體度**（區塊 key `specificity`）

基礎文章：該會期、READY、**單獨發言**（講者只有他一人）、而且 `brief` 不是 null。聯合質詢的摘要卡是整段的，分不出是誰講的，不算進任何一個人。

| key | 名稱 | 值 | n（分母） | 單位 |
|---|---|---|---|---|
| `numbers_per_speech` | 每篇落地數字數 | Σ len(`key_numbers`) ÷ 基礎文章數 | 基礎文章數 | 個／篇 |
| `deadline_asks_per_speech` | 每篇帶期限的要求數 | Σ（`asks` 中 `deadline.strip()` 非空的項數）÷ 基礎文章數 | 基礎文章數 | 項／篇 |
| `sourced_number_share` | 有來源的數字占比 | （`sources` 非空的 key_numbers 數）÷（key_numbers 總數）× 100 | key_numbers 總數 | % |

- `sources` 目前只放法條原文（#9），所以這一項實際上是「數字裡引用法條、而且找得到條文原文的比例」。方法頁照實寫。
- n 為 0 時 `value` 是 null。
- 最小樣本 `MIN_SAMPLE = 5`：n < 5 的人 `sample_ok=false`、`percentile=null`，只顯示原始計數。

### 百分位

- 同儕 = 母體中這一項 `sample_ok` 的人（投入量是整個母體）。
- 百分位 = （同儕中值比他低的人數 ＋ 0.5 × 同值的人數，含他自己）÷ 同儕人數 × 100。存浮點，頁面四捨五入到整數。
- 同儕少於 `MIN_PEERS = 5` 人時，所有人的這一項 `percentile=null`。
- `peers` 欄位存同儕人數，頁面寫「在 N 位同儕中」。

### 快取與重算

- `ProfileStat(person, session, indicator, value, n, percentile, peers, computed_at)`，唯一鍵 `(person, session, indicator)`。
- `compute_profiles()`：先 `assign_sessions()`（替還沒掛會期的文章掛上，並更新每個會期的涵蓋範圍），再逐會期整批重算：同一個 transaction 裡刪掉該會期的舊列、`bulk_create` 新列。冪等，重跑結果相同。
- 管理指令 `python manage.py compute_profiles`：印出每個會期的人數，以及對不到任期的講者名字。
- 排程：每晚匯入（`ingest_ivod`）之後接著跑一次；包在自己的 try 裡，失敗不影響匯入。
- 匯入新文章時（`_upsert` 建立的時候）就掛會期，不必等重算。

## API

### `GET /api/people/{person_id}/profile?source=&session=`

- `source`：可省略。省略時用這個人「最近一個有統計的會期」的來源。
- `session`：會期 id，可省略。省略時用這個來源裡、他發言次數 > 0 的最近一個會期；都沒有就用有統計的最近一個。
- 人不存在、或在這個來源沒有任何統計：404。

```json
{
  "person": {"id": 12, "name": "王小明"},
  "source": "ly",
  "session": {"id": 3, "source": "ly", "term": "11", "name": "第11屆第5會期",
              "start_date": "2026-02-20", "end_date": "2026-05-30"},
  "sessions": [ /* 同來源、他有統計的所有會期，新的在前，形狀同 session */ ],
  "computed_at": "2026-10-01T06:12:00+08:00",
  "min_sample": 5,
  "blocks": [
    {"key": "volume", "title": "投入量", "indicators": [
      {"key": "speeches", "label": "發言次數", "unit": "次", "value": 12, "n": 12,
       "n_unit": "篇", "percentile": 63.5, "peers": 113, "sample_ok": true,
       "evidence_url": "/speaker/%E7%8E%8B%E5%B0%8F%E6%98%8E?source=ly&session=3"}
    ]},
    {"key": "specificity", "title": "具體度", "indicators": [ /* 三項，evidence_url 多帶 &solo=1&brief=1 */ ]}
  ]
}
```

- `evidence_url` 是網站的相對路徑，名字用這個人在該來源任期上的寫法（也就是文章講者欄位的寫法），URL 編碼。
- `n_unit`：投入量與前兩項具體度是「篇」，`sourced_number_share` 是「個數字」。

### `GET /api/articles` 新增三個篩選

- `session`（int）：只要掛在這個會期的文章。
- `solo`（bool）：只要單獨發言（講者欄位沒有「、」）。搭配 `speaker` 時就是講者完全等於這個名字。
- `has_brief`（bool）：只要 `brief` 不是 null。

證據一致性是硬性要求：`speaker=X&source=S&session=K` 的 `count` 必須等於 X 在 K 的 `speeches`；再加 `solo=1&has_brief=1` 必須等於具體度前兩項的 n。測試要直接驗這件事。

### `GET /api/speakers`

每一項多一個 `person_id`（int 或 null）：同來源、同名的任期所屬的人（有多筆時取最新的一筆）。發言者頁靠它找側寫。

## 網站

- 發言者頁（`/speaker/[name]`）：有 `person_id` 時抓側寫，放在報導清單上面。
  - 一行固定說明：「指標由公開公式從既有資料計算，不加總、不排名。」連到 `/method#profile`。issue 寫的是「模型只做分類」，但第 1 步還沒有分類器；具體度用的是摘要卡（模型抽取、程式落地檢查過），方法頁照實說明。
  - 會期切換：列出 `sessions`，連到 `?source=&session=`。標出資料涵蓋範圍與計算時間。
  - 兩個區塊各自一列指標。每個指標：名稱、值與單位、「n = 12 篇」、百分位長條（0～100，標出他的位置）與「第 64 百分位，在 113 位同儕中」；樣本不足時不畫長條，寫「樣本不足（需至少 5 篇）」；同儕不足時寫「同儕不足，不比較」。一個「看這 12 篇」連到 `evidence_url`。
  - 頁面不得出現任何加總分數、排名、名次。
- 發言者頁讀 `session`、`solo`、`brief` 三個網址參數並轉給 `/api/articles`；有篩選時清單上方顯示目前的篩選與「清除」連結。
- 新頁 `/method`：至少有 `#profile` 一節，寫清楚原則、每個指標的公式、聯合質詢的處理、會期與母體的定義、百分位公式、最小樣本、資料限制（只算已完成的文章、舊文章沒有摘要卡、有來源＝法條原文）、還沒做的指標。頁尾加連結。
- 假資料模式（`USE_FIXTURE=1`）要能顯示側寫，方便不連 Pi 也能看版面。

## 測試

- 會期解析：三種來源的實測格式、臨時會、全形數字、解析不出來。
- 掛會期與涵蓋範圍。
- 計算：聯合質詢的次數與時長平分、母體裡沒發言的人是 0、議長副議長不在母體、具體度只算單獨發言且有摘要卡、最小樣本、同儕不足、百分位數值（含同值）、對不到任期的名字有回報、重算冪等。
- API：側寫的形狀、預設會期與來源、404、證據網址；文章篩選；**證據一致性**；speakers 的 person_id。
- 排程在匯入後呼叫重算；匯入建立文章時掛會期。
- 網站：`npm run check` 與 `npm run build` 通過；假資料模式下發言者頁與 `/method` 能顯示。
