# 人物側寫 第二步：議題分布 — 實作設計

日期：2026-10-03　依據：issue #24 的「順序」第 2 步（議題分布），接在第 1 步（PR #25）之後。

原則照 issue：模型只做分類、數字由程式算；只跟同儕比；最小樣本；每個數字能點回去；**模型參與的指標要有人工標註集，準確率低於門檻就不上線**。

## 範圍

做：

1. GPU 端新的工作種類 `topic`：把一段文字分到固定的政策領域。
2. 新聞服務（Pi）：`Topic` 表、每晚替文章分類、標註集（抽樣＋admin 標註）、評估指令、評估通過才計算的議題指標、委員會職掌比對（立委）。
3. API 與網站：側寫多一個「議題分布」區塊、證據篩選、方法頁新章節。

不做：

- **人工標註本身**。標註集要人標，這個 PR 只提供抽樣、標註介面與評估；標完、評估通過之前，議題分布不會出現在網站上。
- 文章頁顯示領域標籤、首頁依領域篩選（issue 沒要求）。

## GPU 端：工作種類 `topic`

- `POST /jobs` 多兩種欄位：`kind`（`"deck"` 預設，或 `"topic"`）；`topic` 工作帶 `text`（必填，上限 4000 字）與 `labels`（`[{key, label, description}]`，2～20 個，key 不重複）。`topic` 工作不需要 `url`；`deck` 工作照舊必填 `url`。
- 跟摘要工作排同一個佇列、同一個工作執行緒（一次只跑一個，避免搶 Ollama）。
- 呼叫 Ollama `/api/chat`，`format` 用 JSON schema：`primary` 的 enum 是各領域的**名稱**，`secondary` 是名稱或 null。溫度 0。名稱再對回 key。
- 提示詞重點：依「這段質詢主要在問什麼」選一個主領域；只有第二個領域占了相當篇幅才填次領域，否則 null；次領域不能跟主領域相同（相同就當成 null）。
- 成品：`{"primary": key, "secondary": key|null, "classifier": "<模型名稱>#topic-v1#<提示指紋>"}`。`topic-v1` 是提示詞版本，改提示詞就要升版。提示指紋是模型實際看到的提示（範本、領域名稱與說明、schema）加上代碼的雜湊前 8 碼：領域清單在新聞服務改，沒人會記得來 GPU 端升版，所以改清單也要自動變成不同的分類器。
- 解析失敗、主領域不在清單裡：工作失敗（不猜）。

## 新聞服務

### 分類的輸入

`one_liner`（摘要卡的一句話）＋各段小標（`Slide.title`），格式：

```
一句話：……
各段小標：
- ……
- ……
```

**不放會議名稱**：「財政委員會」幾乎會直接決定答案，而立委的委員會職掌比對就變成自己比自己。

只分類「已完成、單獨發言、有摘要卡」的文章——跟具體度同一批基礎文章：聯合質詢分不出每個人講了哪個議題，沒有摘要卡就沒有一句話可讀，而評估集也是從這一批抽的。

### 資料表

```
Topic            文章的領域：article（一對一）、primary、secondary（可空）、classifier、labeled_at
TopicLabel       人工標註：article（一對一）、primary（空字串＝還沒標）、note、labeled_at
TopicEvaluation  評估：source、classifier、labeled、correct、accuracy、passed、mistakes（JSON）、ran_at
Membership.committees  JSON 字串清單，立法院同步時存 LYAPI 的「委員會」（「第11屆第5會期：財政委員會」）
```

- 文章重產（`save_result`）時刪掉它的 `Topic`，下一輪重新分類。
- `classifier` 就是 GPU 回來的那串（模型＋提示詞版本＋提示指紋）。

### 每晚分類

`classify_topics(client, limit)`：替基礎文章中還沒有 `Topic` 的送 `topic` 工作、等結果、存起來。失敗只記 log、不動文章狀態；GPU 連不上就整輪停止（同摘要）。排程：匯入 → 分類（上限 `TOPIC_DAILY_LIMIT`，預設 200）→ 重算側寫，各自包 try。

管理指令 `classify_topics [--limit N] [--reclassify]`：`--reclassify` 連已經有 Topic 的也重分（換模型或提示詞之後用）。

### 標註集與評估

- `sample_topic_labels [--per-source 20] [--seed 0]`：每個來源從基礎文章裡隨機抽（固定種子，可重現），建立空白的 `TopicLabel`。已經抽過的不重抽，只補到每個來源 N 篇。
- admin 的「議題標註」頁：清單直接顯示分類器會讀到的那段文字（一句話＋各段小標）與文章連結，主領域用下拉選單**在清單上直接改**，可篩「還沒標」。**不顯示模型的分類**（盲標）。
- `eval_topics`：把**已標註**的文章重新送 GPU 分類（用現在的模型與提示詞），逐來源比對主領域：
  - 準確率 = 主領域相同的篇數 ÷ 已標註篇數。
  - 通過 = 已標註至少 `TOPIC_MIN_LABELS = 20` 篇，而且準確率 ≥ `TOPIC_MIN_ACCURACY = 0.8`。
  - 每個來源存一筆 `TopicEvaluation`，印出各來源結果與每一筆判錯的（文章、人工、模型）。
  - 一次評估裡 GPU 回來的 `classifier` 必須都一樣，不一樣就中止（中途換了模型）。

### 上線的條件

某來源的議題指標**只用**「該來源最新一筆通過的評估」的 `classifier` 分出來的 `Topic`。沒有通過的評估 → 這個來源完全沒有議題指標、API 不給這個區塊。換模型或提示詞之後，新分出來的 Topic 跟通過的版本不同，就不算，直到重新評估通過。

### 指標（區塊 key `topics`）

基礎文章：該會期、READY、單獨發言、有摘要卡、而且有「通過版本」的 Topic。

- 分布：各領域的篇數與占比（篇數 ÷ 基礎文章數）。存成 `ProfileStat` 的 `topic:<代碼>` 列（value＝篇數、n＝基礎文章數、不給百分位）。
- `topic_focus` 聚焦度：最大占比 × 100（%），n＝基礎文章數，套最小樣本，給百分位。
- `topic_breadth` 廣度：占比 ≥ 10% 的領域數（個），n＝基礎文章數，套最小樣本，給百分位。
- `committee_alignment` 委員會職掌內的比例（**只有立法院**）：主領域落在他「那個會期」所屬委員會職掌的篇數 ÷ 有委員會資料的基礎文章數 × 100（%）。n＝有委員會資料的基礎文章數，套最小樣本，給百分位。會期對不上、沒有委員會資料的不算進分母。

委員會職掌對照（寫在程式裡，方法頁公開）：

| 委員會 | 領域 |
|---|---|
| 內政委員會 | 內政治安 |
| 外交及國防委員會 | 國防外交 |
| 經濟委員會 | 財政經濟、農業、環境能源 |
| 財政委員會 | 財政經濟 |
| 教育及文化委員會 | 教育文化、數位科技 |
| 交通委員會 | 交通建設、數位科技 |
| 司法及法制委員會 | 司法法制 |
| 社會福利及衛生環境委員會 | 衛生福利、勞動、環境能源 |

### API

- 側寫的 `blocks` 多一個 `{"key": "topics", "title": "議題分布", "indicators": [...], "distribution": [...], "classifier": {...}}`，只有那個來源有通過的評估時才出現：
  - `distribution`：12 個領域都列（篇數 0 的也列），依篇數由多到少、同數依上表順序：`{key, label, count, share, evidence_url}`；`share` 是 0～100 的浮點數。
  - `classifier`：`{name, accuracy, labeled, evaluated_at}`，頁面用來寫「分類器在 N 篇人工標註上準確率 X%」。`accuracy` 是 0～1（資料庫存的值），`share` 是 0～100。
  - 聚焦度、廣度、委員會職掌的證據網址用 `topic=any`：「被通過版本分過類、哪個領域都可以」，清單篇數才等於 n（沒分到類的不算）。
  - 「有委員會資料」＝那個會期至少有一個委員會在職掌表裡；程序、修憲、經費稽核這類沒有對應領域的委員會不算。一個會期有好幾個委員會時，領域取聯集。
- `/api/articles` 新增 `topic`（領域代碼）：只要主領域是它、而且是該文章來源「通過版本」分出來的。證據網址：`session`＋`solo=1&brief=1`＋`topic=<代碼>`，篇數必須等於分布的篇數（測試要驗）。

## 網站

- 側寫的「議題分布」區塊（API 有給才顯示）：
  - 一行說明：「每篇報導由模型從 12 個固定領域選一個主領域；分類器在 N 篇人工標註上的準確率 X%。只算單獨發言、有摘要卡的報導。」
  - 分布：橫向長條，依篇數排序；每列是領域名稱、篇數、占比，點了連到證據。篇數 0 的領域收在「其他領域都是 0 篇」一行，不畫空長條。
  - 指標：聚焦度、廣度、（立委）委員會職掌內的比例，跟其他指標同樣的卡片與百分位長條。
- 方法頁新增 `#profile-topics` 一節：12 個領域與說明、分類的輸入（為什麼不放會議名稱）、標註集與門檻、上線條件、三個指標的公式、委員會對照表、限制（模型會錯、只算單獨發言）。
- 假資料模式要有一份含議題區塊的側寫。

## 測試

- GPU：`topic` 工作的請求驗證（缺 text、labels 重複或太多、deck 工作缺 url）、schema、回應解析（名稱對回 key、次領域等於主領域變 null、不在清單裡就失敗）、工作執行緒依種類分派、成品格式。
- Pi：分類的輸入文字（不含會議名稱）、只分基礎文章、重產刪 Topic、分類失敗不動文章、GPU 不可用整輪停止；抽樣（每來源 N 篇、固定種子、不重抽）；admin 清單可直接改、不洩漏模型分類；評估（準確率、門檻、篇數不足、classifier 不一致中止、每來源一筆）；上線條件（沒通過沒有區塊、版本不符不算）；三個指標與分布的公式、最小樣本、百分位；委員會解析與對照；證據一致性；排程順序。
- 網站：`npm run check`、`npm run build`；假資料模式下發言者頁有議題區塊、`/method#profile-topics` 有內容。
