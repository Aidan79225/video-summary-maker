# 人物側寫 第四、五步：立委的院內紀錄（出席、提案、表決）— 實作設計

日期：2026-10-03　依據：issue #24 的第 4 步（立法產出）、第 5 步（表決），加上第 1 步延後的出席率。只有立法院；市議會沒有結構化的資料（issue 已寫明）。

不打模型：全部是 LYAPI 的結構化資料，程式計數。

## 探勘結果（2026-10-03 實測 LYAPI v2）

- `/meets`：每場會議有 `會議資料[].出席委員`（姓名清單），院會在第 11 屆有 110 場；`屆`、`會期`、`會議種類`、`會議代碼`、`日期`。
- `/bills`：清單有 `提案人`（陣列）、`議案狀態`、`會期`、`議案名稱`、`提案來源`、`url`；**連署人只在單筆資料裡**，但清單支援 `連署人=<姓名>` 篩選。第 11 屆委員提案 7,402 件。
- `/votes`：**結構化的記名表決**，每筆有 `投票委員`、`贊成`、`反對`、`棄權` 姓名清單、`會議代碼`（例如 `院會-11-5-4`）、`session_period`、`表決議題`、`表決結果`。所以 issue 第 6 步「待驗」的答案是：可以做。

## 範圍

做：`sync_ly_records` 同步三種紀錄；八個指標；紀錄清單的 API 與網頁（證據）；方法頁。

不做：**提案與質詢一致率**。issue 要用第 2 步的分類器替提案名稱分領域，但分類器是在質詢摘要上評估的，議案名稱是另一種文字；依 issue 自己的原則（模型參與的指標要有標註集），要另外一份議案名稱的標註集，留到之後。

## 同步（`articles/ly_records.py`，指令 `sync_ly_records`）

- 參數 `--term`（預設 `LY_TERM`）、`--session N`（只同步某一會期；預設全部會期）。一秒一個請求（同 members_sync 的節奏與 429 退避）。
- 會議：`/meets?屆=&會議種類=院會`，以及 `會議種類=委員會`（分頁）。存 `LyMeeting`：`code`（唯一）、`kind`（院會／委員會）、`term`、`session_number`、`date`（第一天）、`unit`（會議單位，委員會名稱；聯席會議存全部單位）、`attendees`（JSON）。
- 議案：`/bills?屆=&提案來源=委員提案`（分頁）存 `LyBill`：`bill_no`（唯一）、`term`、`session_number`、`name`、`status`、`proposers`（JSON）、`cosigners`（JSON，下一步補）、`url`。連署：對每位該屆委員、每個會期查 `連署人=<姓名>&會期=N`（分頁），把他加進那些議案的 `cosigners`。
- 表決：`/votes?屆=`（分頁）存 `LyVote`：`code`（表決代碼，唯一）、`term`、`session_number`、`meeting_code`、`voted_at`（原文）、`topic`、`yes`、`no`、`abstain`、`voters`（JSON）。
- 冪等：以唯一鍵 upsert。失敗一頁就整個指令失敗、不寫半套（同 members_sync 的原則）。
- 名字：LYAPI 各端點與 `/legislators` 用同一套姓名；比對前去掉空白、間隔號統一（`names.normalize_name`）。
- 黨團：立委同步時把 LYAPI 的 `黨團` 存進 `Membership.caucus`（新北已經用這欄）。
- 會期：每筆紀錄的 `第{term}屆第{session_number}會期` 就是第 1 步的會期名稱；沒有那個 `Session` 就建立（涵蓋範圍仍以文章為準，沒有文章的會期起訖留空）。
- 排程：每週日 `sync_members` 之後跑一次；之後重算側寫。

## 指標（區塊 key `chamber`，標題「院內紀錄」，只有立法院）

都以「該會期、他在任期間」為準（任期日期來自 LYAPI 的到職日、離職日）。百分位、最小樣本、同儕同第 1 步；同儕是該會期的立委母體。

| key | 名稱 | 值 | n | 最小樣本 |
|---|---|---|---|---|
| `plenary_attendance` | 院會出席率 | 出席的院會 ÷ 在任期間的院會 × 100（%） | 在任期間的院會場數 | 套 |
| `committee_attendance` | 委員會出席率 | 出席的「他那個會期所屬委員會」會議 ÷ 那些會議 × 100（%）；聯席會議只要單位裡有他的委員會就算 | 那些會議場數 | 套 |
| `bills_proposed` | 主提案數 | 他是提案人的委員提案件數 | 同值 | 不套 |
| `bills_cosigned` | 連署數 | 他是連署人的件數 | 同值 | 不套 |
| `bills_passed` | 三讀數 | 他主提案、`議案狀態` 含「三讀」的件數 | 同值 | 不套 |
| `vote_participation` | 投票出席率 | 他有投票的記名表決 ÷ 在任期間的記名表決 × 100（%） | 在任期間的表決數 | 套 |
| `caucus_agreement` | 與所屬黨團一致率 | 他的票（贊成／反對／棄權）跟所屬黨團多數相同的表決 ÷ 他有投票、而且黨團有多數的表決 × 100（%） | 分母 | 套 |
| `caucus_defections` | 跨黨投票數 | 他的票跟所屬黨團多數不同的表決數 | 同值 | 不套 |

- 黨團多數：那次表決中，同黨團有投票的人裡票數最多的選項；並列就是沒有多數，那次不算進一致率與跨黨投票。黨團用他在那個會期的任期上的 `caucus`；沒有黨團（無黨籍未參加黨團）就不算這兩項（值 null、n 0、`reason="no_caucus"`）。
- 「不加總、不排名」照舊；方法頁寫明：出席、投票多不代表比較好，跟黨團不一致也不代表好或壞。

## 證據（紀錄清單）

- API `GET /api/people/{id}/records?session=&kind=`：`kind` 是 `plenary`、`committee`、`proposed`、`cosigned`、`passed`、`votes`、`defections`。回傳該人該會期的那一類紀錄，每筆附官方連結：議案用 `url`；會議與表決給日期、名稱、會議代碼與他的出席或票（表決另附他黨團的多數）。筆數必須等於指標的 n（或值），測試要驗。
- 每個院內紀錄指標的 `evidence_url` 是網站的 `/records/{person_id}?session={id}&kind=...`。
- 網站新頁 `/records/[id]`：標題寫是誰、哪個會期、哪一類，列出紀錄與官方連結，可切換類別，回到發言者頁的連結。

## API 與網站

- 側寫 `blocks` 在立法院多一個 `chamber` 區塊（沒有同步過紀錄的會期就不給這個區塊）；指標卡沿用；一致率沒有黨團時寫「沒有參加黨團」。
- 方法頁 `#profile-chamber`：資料來源與同步頻率、每個指標的公式、黨團多數的定義、在任期間的處理、限制（LYAPI 的資料延遲、聯席會議的處理、為什麼沒有提案與質詢一致率）。
- 假資料模式：一位立委的院內紀錄區塊與一頁紀錄清單。

## 測試

- 解析：三種端點的實測資料形狀（存成 fixture）、分頁、429、失敗不寫半套、冪等、連署的補法、姓名正規化、黨團。
- 指標：在任期間的分母、聯席會議、黨團多數與並列、沒有黨團、三讀判斷、最小樣本與百分位。
- 證據：每個指標的紀錄清單筆數等於 n 或值。
- 網站：check、build、假資料模式的區塊與 `/records` 頁。
