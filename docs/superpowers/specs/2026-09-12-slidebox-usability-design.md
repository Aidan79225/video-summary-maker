# SlideBox 三個使用痛點的設計（2026-09-12）

使用者提出、並授權在他吃午餐時自動完成：

1. 目前是用 `v=` 後面的 hash 當資料夾名稱，難分辨
2. 只能一片片貼；等生成的時候看到其他影片想接著做
3. 有些時候想要詳細完整的內容，但不想去看影片

分支 `feat/usability`，疊在 `feat/speech-transcription` 上——痛點 1 與 3 會動到語音功能碰過的同一段程式碼（use case 的輸出路徑、`Deck`／`Slide` 實體），分開做只會衝突。

---

## 1. 輸出資料夾命名

**做法**：`usecases/naming.py` 的純函式 `deck_folder_name(title, video_id)`，產出 `影片標題 [影片id]`。

**裁定：保留 id，而不是只用標題。** 標題放前面才看得出是哪支影片，但 id 有兩個實際作用——同名影片（真的存在）不會互相覆蓋，而同一支影片重跑會寫回同一個資料夾、不會每次長出一個新的。代價只是資料夾名尾端多 11 個字。

**裁定：標題截到 80 字。** 加上 `" [id]"` 之後仍遠低於 Windows 的路徑長度限制，使用者還能把輸出資料夾放在較深的位置。

Windows 檔名處理：移除 `\ / : * ? " < > |`，控制字元換成空格（刪除會讓換行兩側的字黏在一起），壓縮連續空白，去掉結尾的點與空白（Windows 會靜默去掉或直接建立失敗，之後拿同一個路徑寫檔就找不到）。標題清乾淨後若什麼都不剩，退回只用 id。

實測：`발표잘하는법 따라해보세요! [NZkVcvVd2OQ]`。

---

## 2. 生成佇列

**做法**：`usecases/queue.py` 的 `JobQueue` / `QueueItem`，純資料與規則，不碰執行緒也不碰 UI。`DeckPage` 加一個 `QListWidget`，網址列在生成中保持可用。

排隊規則全部可單元測試，UI 只負責接按鈕。這一層的接線錯誤（signal 接到錯的項目、跑完沒接續、生成中把網址列鎖住）純邏輯測試看不到，所以另外用離屏 Qt 跑真的 `QThread` 驗證六個情境。

**裁定：失敗不停佇列。** 使用者排完通常就去做別的事了；一支失敗讓整排停下，等於整晚白等。代價是設定打錯（例如模型名稱）時會連續失敗好幾項。

**裁定：取消停下整個佇列。** 取消的意思是「停下來」，不是「跳過這支繼續下一支」。剩下的維持等待，按「開始」繼續。代價是想跳過單一項目時要多按一次「開始」。

**裁定：同一時間只跑一項。** 兩個生成會互搶 ffmpeg 與 Ollama，而 UI 只有一條進度，使用者分不出哪個在動。代價是多核機器的吞吐沒吃滿。

**裁定：生成中仍鎖住設定，只放開網址列。** `Settings` 是共用的可變物件，正在跑的那一項會即時讀到改動，行為變得不一致。代價是要換模型或改「詳細」時必須先取消。

**裁定：擋重複只擋還沒跑完的網址。** 連按兩下加入會白等一倍時間；而已經跑完的影片再排一次是正當需求（換了模型、或這次想要詳細版本）。

**接線細節**：worker 的 signal 用預設引數綁住當下那一項，不用「目前執行中的項目」——signal 送達時執行中的可能已經換人，會把 A 的成品記到 B 身上，使用者點開第二項看到第一支影片。

## 3. 詳細內容

**做法**：`Settings.detailed` 一個開關，同時做兩件事——

1. `Slide.detail`：模型對每個章節多寫一段 150～300 字的完整敘述
2. `Deck.transcript_text`：HTML 末尾附上完整逐字稿，預設收合

**裁定：一個開關做兩件事，不拆成兩個選項。** 使用者的話是「想要詳細完整的內容但不想看影片」。摘要一定有損，逐字稿是唯一無損的那一份；兩者一起才回答得了那句話。拆開只是把決定丟回去。

**裁定：每頁敘述限 150～300 字。** 15 頁 × 300 字加上原本的字幕，總量才不會逼近 `num_ctx`。超出時 Ollama 會從頭截斷提示，症狀是「摘要只涵蓋影片後半段」，而且沒有任何錯誤訊息。

**裁定：`detail` 放進 JSON schema 的 `required`。** 只加進 `properties` 而不 `required`，小模型會直接省略——使用者勾了「詳細內容」卻拿到跟一般模式一樣的成品，還完全看不出原因。

**裁定：逐字稿維持字幕原文，標題誠實寫成「完整逐字稿（字幕原文）」。** 翻譯數萬字要再跑好幾輪模型，時間多一倍以上，而詳細敘述已經是中文的完整版本。代價是外語影片的附錄只能當時間軸索引用。

**裁定：逐字稿不套用字元預算。** `compress_cues` 的預算是為了不超過模型的 context；附錄是給人讀的，不進模型，沿用預算只會讓長影片的每一段都被截掉半句話——附錄的價值就在於完整。時間標記從秒數換成 `mm:ss`（秒數是為了讓模型好抄，人看的是另一回事）。

### 端到端實測抓到的兩個 bug

**詳細敘述整段照抄韓文原文。** 第一次實測（韓文影片，5 頁），`title` 與 `bullets` 都是繁體中文，但 `detail` 五段全是韓文字幕原文——「把這段影片實際說了什麼完整寫出來」這句話把模型推向逐字複製。修法是在 system 提示最前面加上「所有輸出一律使用繁體中文。影片若是外語，翻譯成繁體中文再寫，不要照抄原文」，並在 `detail` 的欄位說明裡明寫「**嚴禁照抄字幕原文**」。

**composition root 的轉發層沒跟上 port 的新參數。** `Summarizer.summarize` 加了 `detailed`，但 `build_main_window` 裡那個區域類別 `_CurrentSummarizer` 的簽章少一個參數——所有單元測試都綠，使用者按下生成才會炸成 `TypeError`。修法是把它提升成模組層級的 `CurrentSettingsSummarizer`，並加一個用 `inspect.signature` 比對 port 與實作的測試，讓同一類錯誤下次在測試就被擋下。
