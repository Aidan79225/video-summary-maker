# 事實查核與查證相符率（2026-09-19）

使用者要求：每位立委或官員都可能說錯或說謊，想要一個「信任分數」的感覺，而且要看得到**查了什麼東西**來評斷——要有根據，不是直接問 LLM 給分數。

## 核心原則

**LLM 永遠不產生分數，也不自己判斷數字。** 它只做兩件事：

1. 從逐字稿挑出「可以用官方資料驗證」的陳述，並整理成結構化的主張
2. 在沒有數字可比的時候，判斷一段**我們自己取回來的**證據文字支不支持那個主張——而且必須逐字引用證據裡的句子，引用不在證據裡就作廢

證據由程式去官方資料取回，數字由程式比對，分數由公開公式從逐則判定算出。每一則判定都附上來源網址與原文摘錄，任何人都能從分數一路追到「查了哪一條法條」。

## 裁定

以下前四項是使用者在 brainstorming 時逐一選定的，其餘依建議實作。

**裁定：人工只審「不符」。** 「相符」「部分相符」「無法查證」自動發佈；「不符」先進審核佇列，經人工核准才公開、才計入分數。真正會傷人（也有誹謗風險）的是把具名的人標成「講錯」；其他兩類判錯了不會傷到誰。語音辨識錯字（實測「非紅供應鏈」被聽成「飛鴻公園」）最容易被誤判成「不符」，這一關正好擋住。

**裁定：證據只用官方資料，第一版只用 LYAPI 的法律與議案。** 使用者選了「官方資料」。實測可行的範圍：

| 主張種類 | 證據來源 | 實測例子 |
|---|---|---|
| 現行法條內容（罰則、期限、金額） | `law_contents`，取**發言當日有效**的版本 | 邱慧洳「現行罰鍰 3 萬到 5 萬」↔ 醫療法第 106 條「違反第二十四條第二項規定者，處新臺幣三萬元以上五萬元以下罰鍰」 |
| 議案內容（誰提的版本、編列多少） | `bills` 的 `對照表`、`案由` | 徐巧芯「行政院版 6 年 2100 億」↔ 行政院「國防自主無人載具採購特別條例草案」第五條「經費上限為新臺幣二千一百億元」 |
| 議案進度（是否三讀、目前狀態） | `bills` 的 `議案狀態` | — |

政府統計（主計總處、資料開放平臺）介面各自不同，留到第二版。事實查核中心的報告也留到之後。

LYAPI（`ly.govapi.tw`）是公民科技社群整理的服務，不是立法院官方。所以每筆證據存**兩個網址**：`official_url` 指向官方頁面（議案用 `ppg.ly.gov.tw` 的議案頁；法律用全國法規資料庫的名稱查詢頁），`api_url` 指向 LYAPI 的那筆紀錄（可重現取得的內容）。

**裁定：第一版只查核立委本人的陳述。** 實測逐字稿**沒有講者標記**，只有時間與文字。院會的政黨發言是委員獨白，歸屬可靠；委員會質詢有問有答，但分不出哪句是部長講的。所以只查核該片段的委員（`委員名稱`），官員的回答不收。官員留到有講者分離之後。

**裁定：模型用本機的 `qwen3.5:9b`，放在介面後面。** 數字比對交給程式，模型只負責抽取主張與文字判讀。上線前用人工標註樣本量準確率；不夠好再換模型，換的時候只動 composition。

**裁定：分數是「查證相符率」，不是「誠信分數」。** 我們能查的是「說的和資料對不對得上」，查不到「是不是故意說謊」——說錯、口誤、語音辨識錯字在資料上長得一樣。說「某人的陳述與公報不符」是事實陳述，說「某人說謊」是對人格的評價。

**裁定：查核跑在 GPU 主機，當成摘要 API 的另一種工作。** 它需要模型，而 Pi 不跑模型；放進同一個工作佇列，才不會和摘要互搶 Ollama。Pi 只負責送工作、存結果、開 API、給人審核。

## 判定規則

四種判定：

| 判定 | 意思 | 何時 |
|---|---|---|
| 相符 `supported` | 證據支持這個主張 | 主張的每個數字都出現在證據裡；或模型判讀為支持且引用成立 |
| 部分相符 `partial` | 一部分對得上 | 主張有多個數字，只有一部分出現在證據裡 |
| 不符 `contradicted` | 證據與主張衝突 | 證據裡有同類數字但全都對不上；或模型判讀為衝突且引用成立 |
| 無法查證 `unverifiable` | 沒有足夠的證據 | 找不到對應的法條／議案；模型說證據不足；模型的引用不在證據裡 |

**數字比對**（`method = numeric`）：

- 程式從**主張原文**（不是模型的轉述）抽出數字，從證據文字抽出數字，都正規化成數值與單位類別（金額「元」、期間「年／月／日」）
- 要處理：阿拉伯與中文數字混寫（`3萬`、`三萬元`、`二千一百億元`、`2100億`）、範圍共用單位（`5到25萬` = 5 萬到 25 萬）
- 只比同一單位類別。主張裡的數字集合 ⊆ 證據裡的 → 相符；部分 ⊆ → 部分相符；證據有同類數字但交集為空 → 不符；證據沒有同類數字 → 改走文字判讀
- 主張原文有「約、大約、將近、超過、逾」時，允許 10% 誤差；否則必須相等

**文字判讀**（`method = model`）：模型收到主張與證據摘錄，回 `{verdict, evidence_quote, reason}`。程式檢查 `evidence_quote` 必須是證據文字的子字串（忽略空白），不是就改判無法查證。

**主張本身也要落地**：模型抽出的 `quote` 必須是逐字稿的子字串（忽略空白與時間標記），不是就丟掉——否則模型可能「幫委員說了他沒說的話」。

## 分數

對每位委員，只算已公開的判定（自動發佈的，加上人工核准的「不符」），**「無法查證」不計入**：

```
n = 相符 + 部分相符 + 不符
查證相符率 = (相符 + 0.5 × 部分相符 + 1) / (n + 2)
```

`+1 / +2` 是拉普拉斯平滑：樣本少時往 50% 靠，一則不符不會變成 0%。**n < 5 時不顯示百分比**，只顯示「樣本不足（3／5）」與各類的數量。任何時候都同時顯示 n 與各類數量，例如「87%｜15 則可查證陳述中 13 則相符」。

公式、判定規則、資料來源與限制，全部寫在前端的「查證方法」頁。

### GPU API

`Job` 加上 `kind`（`deck` | `factcheck`）與 `params`。執行緒依 `kind` 分派到對應的執行函式；佇列、取消、單一執行的規則完全不變。

```
POST /factchecks   {speaker, date, meeting, transcript_text, model?}  → 202 {id, status}
GET  /jobs/{id}    → result:
{
  "model": "qwen3.5:9b",
  "claims": [{
    "quote": "滋擾醫院秩序之人 他的行政罰鍰從現行的3萬到5萬",
    "timestamp": 32.0,
    "kind": "law_article",
    "statement": "醫療法現行對妨礙醫療業務者的罰鍰為 3 萬到 5 萬元",
    "subject": {"law": "醫療法", "article": "第24條"},
    "verdict": "supported",
    "method": "numeric",
    "rationale": "主張的金額 30,000、50,000 元都出現在證據中",
    "evidence": [{
      "source": "law", "title": "醫療法 第一百零六條（2026-05-08 修正版）",
      "official_url": "https://law.moj.gov.tw/…", "api_url": "https://ly.govapi.tw/v2/law_contents?…",
      "excerpt": "違反第二十四條第二項規定者，處新臺幣三萬元以上五萬元以下罰鍰…"
    }]
  }]
}
```

### 取證細節（實測得來）

- **法律名稱 → 編號**：`/laws?q="醫療法"`。`q` 一定要加引號，不加會變成模糊搜尋（實測搜「醫療法」回傳所得稅法）。取 `名稱` 或 `其他名稱` 完全相符的那一筆
- **發言當日有效的版本**：`/laws/{id}/versions`，取日期 ≤ 發言日期的最新一版，再用它的 `版本編號` 查 `law_contents`。醫療法最近一次修正是 2026-05-08，查錯版本會把「修法前說的對」判成錯
- **條號是中文數字**：`第一百零六條`。程式把 `24條`、`第24條` 轉成 `第二十四條`
- **委員引的條號不一定是罰則那條**：邱委員說第 24 條，罰鍰在第 106 條（「違反第二十四條第二項規定者…」）。所以取證時除了指定條文，也取「內文提到該條」的其他條文，最多 3 條
- **議案**：`/bills?q="<關鍵字>"&屆=<屆>`，再用 `提案單位/提案委員` 比對提案者（「行政院」「國民黨黨團」「委員某某等」），只取提案日期 ≤ 發言日期的。證據取 `對照表` 中含數字的條文與 `案由`

### Django

- `FactCheckRun`（一對一 Article）：`status`、`attempts`、`gpu_job_id`、`error`、`model`、`checked_at`。沿用 `ingest` 的模式：可重跑、嘗試次數有上限、斷線後先問 GPU 工作是否已完成
- `Claim`（FK Article）：`quote`、`timestamp`、`kind`、`statement`、`subject`(JSON)、`verdict`、`method`、`rationale`、`review_status`（`auto` | `pending_review` | `approved` | `rejected`）、`reviewer_note`、`reviewed_at`
- `Evidence`（FK Claim）：`source`、`title`、`official_url`、`api_url`、`excerpt`
- 公開規則：`review_status in (auto, approved)`。`contradicted` 落地時一律 `pending_review`
- **重跑不能洗掉人工審核**：已有 `approved` 或 `rejected` 的文章不重跑，除非 `--force`
- `factcheck_articles` 指令：處理已完成摘要、尚未查核的文章；`run_scheduler` 在匯入後接著跑

API（掛在既有的 `/api` 下）：

```
GET /api/articles/{slug}        → 多一個 claims（只含公開的）
GET /api/speakers               → 每位委員多一個 factcheck 摘要 {rate, n, supported, partial, contradicted, unverifiable}
GET /api/speakers/{name}/claims → 該委員公開的逐則判定，含證據
```

### 前端

- **文章頁**：摘要段落之後、完整逐字稿之前，一個「查證」區塊。每則：主張原文（可跳回影片時間）、判定標籤、比對方式（數字比對／模型判讀）、證據標題與摘錄、官方連結。區塊開頭固定說明「自動查核；『不符』經人工確認後才顯示」
- **委員頁**：查證相符率（或「樣本不足」）、各類數量的比例條、逐則清單
- **`/method` 查證方法**：資料來源、四種判定、公式、人工審核規則、已知限制
- 判定顏色是語意色，與強調色分開：相符綠、部分相符琥珀、不符紅、無法查證灰

## 準確率評估

`scripts/eval_factcheck.py`：讀人工標註的 `(文章, 主張, 正確判定)` JSONL，跑整條 pipeline，輸出混淆矩陣。重點看兩個數字：

- **「相符」的精確率**——這一類自動發佈又計分，判錯會灌高分數
- **「不符」的召回率**——漏掉的會被當成相符或無法查證

第一批標註用這次匯入的 10 篇真實文章。

## 錯誤處理

- LYAPI 查不到或逾時 → 該則「無法查證」，原因寫進 `rationale`；整篇不失敗
- 模型輸出不是合法 JSON → 用 Ollama 的 `format` 做文法約束（沿用 slidebox 的做法）；仍失敗則整篇工作失敗、下次重試
- 一篇沒有任何可查證的主張 → 正常完成，`claims` 為空

## 測試

- 純邏輯（數字正規化、比對規則、落地檢查、公式、版本挑選、條號轉換）用單元測試釘住
- LYAPI adapter 用注入的假 `fetch`，fixture 取自實測的真實回應
- GPU API 的 `kind` 分派與既有佇列測試並存
- Django：模型、公開規則、審核動作、重跑保護、API 形狀
- 前端：`astro check`，並更新示範資料讓 `USE_FIXTURE=1` 也看得到查證區塊

## 不做的事

- 不查核官員（沒有講者標記）
- 不用統計資料、新聞、事實查核中心（第二版）
- 不做「說謊」的判斷，也不做跨時間的「前後矛盾」比對
- 不讓讀者在網站上申訴或留言（審核只在 admin）
